# 0550 separate supply proposal draft and B scope

2-Nov-2026, Asia/Bangkok. Parent2ece6ad8, UI2026-11-02.2-preview.

## Owner-authorised scope

Implement steps1–2: distinguish external supplier versus ADDVALUE direct proposal,
separate upstream purchase cost from a new package selling proposal, and include
associated B activities. Price figures are a separate later task. Do not apply the
earlier DMR or PAGA example amounts/percentages to existing financial records.
Do not create new navigation modules or change source/Working/Release identities.
Paused Volume I navigation is excluded from this change.

## Implemented

- An optional typed `line.supplyDraft` on existing PartA owners stores seller role,
  manufacturer, procurement channel, draft quotation reference, independent
  currency/unit, fixed package selling input or cost-markup input, remaining
  final-margin/prime policy fields, scope basis and B allocations. New price and
  package-markup inputs are blank. No startup seed or price migration is added.
- Existing `vendorId/offerId/manualCost/quantity/sellMode/sellRate/markupPct/
  marginPct/primePct` remain the sole active monetary inputs. No supplier offer is
  rewritten, no price row is selected or deselected, and no FX is changed.
- The existing Working editor shows the draft beside the unchanged upstream cost.
  The direct-supply principle is shown using existing E10/E11→E12→E13; this phase
  does not run that draft as a second pricing engine or activate any result.
- Each draft B allocation references an existing B Working owner by ID and records
  REVIEW/INCLUDED/SEPARATE plus evidence/basis. Existing Integration activities are
  read through their canonical `workLineId`, including requirement, responsibility,
  driver quantity/unit, deliverable and current draft/review status. No activities,
  quantities, manpower, rates or paid work are generated by opening this view.
- A opens the referenced B Working line; the B editor shows reverse A package links.
  Inclusion while B remains additive, inclusion in multiple draft owners, missing B
  owners, unselected separately charged B and missing SI activity links are explicit
  authoring diagnostics. Missing/deleted B IDs are retained rather than refilled.
- INCLUDED is a proposed allocation, not a cost exclusion: it never subtracts B,
  sets its price to0 or stamps technical/engineering approval. B scope/cost must
  be reconciled before a future price activation. Partial scope within a shared B
  owner still needs engineering and commercial judgement.
- Draft metadata is excluded from active Official line-price, technical record,
  Volume I binding and current release dependency keys, including an included
  price owner's draft. No customer price/form cells read it.
  Canonical backups retain and validate it; old workspaces without the field work.
  Existing frozen issue snapshots/outputs and their active dependency keys are
  unchanged. The raw draft remains in the canonical backup/snapshot as an
  inactive authoring record; no current issue is invalidated by that field alone.

## Relevant ADR principles and boundaries

ADR-0550-001 §§2–6,8–12: separate source cost versus commercial interpretation,
retain many-to-many requirements/activities, one cost owner, visible unresolved
scope, shared canonical records, stable module IDs and frozen history. Existing
WP/Official/Release gates remain in force. Authoring diagnostics are not proof
of project-wide source completeness, supplier adequacy or avoidance of every
possible overlap. This phase provides no activation/approval path for new prices.
